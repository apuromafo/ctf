## Metodología / Methodology

1. **Paso / Step:** Obtener credenciales y hashes mediante DCSync con Mimikatz / Obtain credentials and hashes via DCSync with Mimikatz.
2. **Paso / Step:** Identificar el hash NTLM de krbtgt para forjar golden/silver tickets / Identify the krbtgt NTLM hash to forge golden/silver tickets.
3. **Paso / Step:** Usar ForgeCert.exe para falsificar certificados cuando se tiene la clave privada de la CA / Use ForgeCert.exe to forge certificates when the CA private key is available.
4. **Paso / Step:** Pasar tickets (kerberos::ptt) desde archivos .kirbi / Pass tickets (kerberos::ptt) from .kirbi files.
5. **Paso / Step:** Inyectar SID History en atributos de objetos y reiniciar el servicio ntds / Inject SID History into object attributes and restart the ntds service.
6. **Paso / Step:** Abusar del group nesting y de las ACLs de AdminSDHolder/SDProp para persistencia / Abuse group nesting and AdminSDHolder/SDProp ACLs for persistence.
7. **Paso / Step:** Gestionar GPOs para acceso local mediante Restricted Groups y Delegation / Manage GPOs for local access via Restricted Groups and Delegation.

### Cadena de ataque / Attack Chain

```
Credential Hunting: lsadump::dcsync /domain:za.tryhackme.loc /user:test
  -> Obtener hash NTLM de krbtgt (16f9af38fca3ada405386b3b57366082)
    -> Crear Golden Ticket (impersona TGT, 10 años de vida) o Silver Ticket (impersona TGS)
      -> ForgeCert.exe para falsificar certificados con private key
        -> Pasar tickets: kerberos::ptt ticket.kirbi
          -> Inyectar SIDHistory (con ntds.dit) y reiniciar servicio: Start-Service -Name ntds
            -> Abusar de Group Nesting y ACLs de AdminSDHolder
              -> Modificar GPOs: Restricted Groups y Delegation para persistencia
```

**Lección:** La persistencia en Active Directory se puede lograr mediante múltiples vectores: robo de credenciales y tickets (golden/silver), inyección de SID History, abuso de group nesting y manipulación de ACLs a través de AdminSDHolder y GPOs. Cada técnica explota componentes centrales de la autenticación y autorización de AD.
