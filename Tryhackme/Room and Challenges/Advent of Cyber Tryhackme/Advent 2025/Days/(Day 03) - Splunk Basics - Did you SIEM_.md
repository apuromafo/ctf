## Solucionario

### Día 03: Splunk Basics - Did you SIEM_

**Explicación:** Apuntes del laboratorio (notas bilingües originales):

- Splunk: Data processing platform; parses logs into a readable format and allows fast query of logs
- log sources (source type)
  - web_traffic: web connections to and from the web server
  - firewall_logs: shows if logged traffic was allowed or blocked
- histogram: spike in activity -> attack window
- fields:
  - `#` - automatically extracted fields (generated by time commands)
  - `a` - manually added
- User agent: indicates what software initiated the web request
- URI (unique resource identifier): can be used to access a resource on a web server(if manipulated)
- Firewall logs show if the attacker gained access, established a connection, etc.
- Directory traversal: ../../etc/passwd
- Automated SQLi tools: Havij, sqlmap

**Códigos / Codes**
- 504: Successful SQL injection
- 401, 403, 404: unauthorized response, forbidden, page not found

| # | Pregunta | Respuesta |

| 2 | Which day was the peak traffic in the logs? (Format: YYYY-MM-DD) | `2025-10-12` |
| 3 | What is the count of Havij user_agent events found in the logs? | `993` |
| 4 | How many path traversal attempts to access sensitive files on the server were observed? | `658` |
| 5 | Examine the firewall logs. How many bytes were transferred to the C2 server IP from the compromised web server? | `126167` |

---

**Metodología:**

1. Consultar el log source `web_traffic` y ordenar por volumen (histogram) para localizar la ventana de ataque

2. Filtrar por IP de origen y user agent para identificar al atacante

3. Buscar eventos del user agent de herramientas SQLi (Havij) y de path traversal (`../../etc/passwd`)

4. Analizar `firewall_logs` para cuantificar los bytes hacia la IP del C2

**Learning chain:** Splunk query -> Source types -> Histogram -> Fields -> Firewall logs

**Lección:** *Splunk convierte logs brutos en datos consultables: el histograma revela la ventana de ataque y los user agents (como Havij) o patrones como `../../etc/passwd` permiten correlacionar SQLi y path traversal con el exfiltrado final hacia el C2.*

**MITRE ATT&CK:**

- T1190 - Exploit Public-Facing Application

- T1083 - File and Directory Discovery

- T1082 - System Information Discovery (directory traversal)

- T1041 - Exfiltration Over C2 Channel
